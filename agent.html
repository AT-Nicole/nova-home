3 天怎么跑：从你的真实资料开始

不拿示例客户演示。你带 3–5 个真实询盘或客户名进来，我们用它们跑完整链路——跑不动的部分当场说跑不动。

DAY 1

喂料：把你的生意装进去

产品资料、规格表、报价口径、账期底线、典型客户与历史邮件，整理成本机知识库。

同时定验收口径：这 3 天结束时，哪些东西必须在你手上。

产出：本机知识库 + 验收清单
DAY 2

研判：一封一封拆开

逐条拆询盘：要什么、急不急、预算真假、有没有坑；再背调客户、拆竞品动作、标出谈判筹码。

你随时打断、纠正——这是陪跑，不是放录像。

产出：客户画像 + 优先级 + 风险标注
DAY 3

落 SOP：人接着就能干

把判断变成规则：A/B/C 分层标准、每层触发动作、首封与三封跟进的写法；线索进飞书，跟进计划自动生成。

最后交底：哪些能信、哪些必须人工复核，写清楚。

产出：开发信序列 + 分层 SOP + 飞书线索库

常见问题

问得最多的六个，含我们最不想被问的那个。

我们 3 个业务员能不能同时用？

不能舒服地同时用。1 位独占很顺，2 位以上会明显变慢、思考时间拉长——这是 32G 统一内存单机的真实上限，我们不在宣传里绕开它。要多人同时用：走基础版（云端 API，并发由云端保证），或上私有化版按人数配算力。

客户资料会不会被传到公网？

体验版的推理在本地机器上完成，不调用公网大模型接口，资料不经过第三方模型服务。远程演示走加密通道，屏幕共享只给你看结果，不导出你的原始文件。演示结束后可按约定删除并出书面确认；涉密资料建议先脱敏。

3 天到底能交付什么？会不会只是聊了三天？

交付物是四件能拿走的东西：开发信序列（3 类客户 · 首封 + 跟进三封）、客户分层 SOP（判定规则 + 触发动作）、询盘研判记录（用你的真实询盘逐条标风险）、飞书线索库（字段与跟进计划建好）。验收按可控项过：链路跑通、四件交付物齐、你的人能复述规则。做不到的部分，当场写「没做到」。

它和 ¥399/月 的基础版，差在哪？

差的不是功能多少，是谁来算、数据去哪。基础版走云端 API：便宜、多人、稳定，适合日常翻译改稿出文案；演示版用本地 R1 推理：慢一点，但能一次吃进整包客户资料做深度研判，数据不出机器，而且交付的是 SOP 不是聊天记录。一个按「工具」卖，一个按「陪跑交付」卖。

能不能装到我们公司机房？

可以，走私有化部署版（¥3 万起，常见 3–15 万）：客户自购服务器（N 卡更合适），我们负责部署 R1 16B / 32B、喂企业数据、对接 CRM/ERP、培训与运维手册。我们这台样板机只用于演示和打样，不交付给客户长期商用。

效果怎么衡量？你们承诺询盘吗？

不承诺询盘数，也不承诺成交——那取决于你的产品、价格和市场，不是模型决定的。我们承诺的是可控项：链路跑通、四件交付物齐、业务员能复述规则并能独立用起来。真实询盘与回款按台账记录，没有就写 0，这条规矩我们对自己也适用。
